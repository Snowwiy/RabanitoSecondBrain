# Orden de versiones Python y contraste OSV local

`rabanito/pep440.py` implementa un parser propio y acotado del orden de versiones PEP 440 con biblioteca estándar. No utiliza ni instala packaging, pip o uv; no resuelve dependencias, ejecuta paquetes o hace red. Lo usa el motor de análisis6, compartido por SBOM, requisitos exactos, uv.lock y pylock.toml.

## Contrato y límites

Se admiten epochs, releases de longitud variable con ceros equivalentes, alpha/beta/rc y sus alias, post/dev, números implícitos, separadores y prefijo v. El parser normaliza mayúsculas y whitespace ASCII exterior. Presupuesto:200caracteres tanto de entrada como en la forma canónica, solo ASCII; el límite también acota enteros, segmentos y trabajo. Una expansión canónica que supera ese presupuesto no produce una conclusión negativa de rango. Unicode/whitespace interior, versiones legacy y sintaxis de specifiers se rechazan sin incluir el texto de entrada en errores. No se anuncia compatibilidad sin límites con todas las cadenas que aceptaría un gestor.

`parse_version(value)` devuelve `Version(normalized, key, has_local, numeric_final)` o None. La key permite ordenar también labels locales. `public_version_key` y el adaptador `dependencies.python_release_key` excluyen builds locales del contraste automático.

Las listas explícitas OSV conservan precedencia de coincidencias literales positivas. Se reconoce equivalencia de versiones públicas normalizadas; la evidencia distingue `pep440_public_version_equivalence` de `pep440_numeric_release_equivalence` y `explicit_affected_version`. El límite de20000versiones coincide con el normalizador OSV; nunca se trunca silenciosamente una lista para concluir fuera de un rango. Una lista mayor requiere revisión.

Los rangos PyPI ECOSYSTEM usan orden de versiones, **no reglas de selección de pip**. introduced abre un intervalo inclusivo; fixed/limit cierran exclusivamente y last_affected inclusivamente. introduced="0" conserva su significado especial OSV. Se valida el stream completo; formas no evaluables, streams inválidos/no soportados o límites locales requieren revisión. No se excluye un prerelease solo porque pip pudiera excluirlo al aplicar un specifier.

Un label local puede representar cambios downstream desconocidos: no se trata como release público equivalente ni parche verificado. El resultado es `needs_review`/`local_build_applicability_not_verified`, salvo coincidencia literal explícita positiva en el aviso. Los labels locales en límites tampoco permiten una conclusión negativa automática. Ningún resultado declara instalación o seguridad.

Fuentes primarias consultadas: [PyPA: versiones y normalización](https://packaging.python.org/en/latest/specifications/version-specifiers/), [esquema OSV](https://ossf.github.io/osv-schema/), [helper PyPI oficial de OSV](https://github.com/google/osv.dev/blob/master/osv/ecosystems/pypi.py) y [implementación de referencia PyPA](https://github.com/pypa/packaging/blob/main/src/packaging/version.py). El código de referencia solo se inspeccionó; no se descargó para ejecutarlo ni se convirtió en dependencia. OSV también admite versiones legacy; este lector las deja sin evaluar salvo coincidencia literal positiva.

## Integración y caché

La CLI `dependency inspect` no cambia opciones ni crea endpoints nuevos. Mantiene citas, localizadores, cobertura y presupuestos; los informes incluyen engine_version6 (la ampliación PEP440 apareció en5). La caché no reutiliza motores anteriores, pero no borra snapshots. Persistir un informe o revisión conserva el flujo de autorización explícita. No cambian DependencyDDL1 ni KG1/motor3; el grafo recibe nuevos snapshots únicamente cuando se guardan de forma autorizada. No se reproyecta toda la base por cambiar el orden de versiones.

## Validación

Pruebas locales cubren orden por pares de sufijos, normalización, límites, epochs y releases largos, builds locales, listas explícitas, intervalos disjuntos/malformados, SemVer/ecosistemas no soportados, requisitos/SBOM/uv.lock, citas CLI, solo lectura, caché y restauración. La suite anterior conserva sus pruebas, actualizando expectativas donde el comportamiento nuevo es intencionado.

Un GET acotado por ID de [un aviso público real de requests](https://api.osv.dev/v1/vulns/GHSA-9wx4-h78v-vm56) permitió un ensayo offline sobre copia desechable:151versiones enumeradas por el proveedor y6probes de orden expresamente diferenciados de releases publicadas.157componentes:152candidatos,4fuera de intervalos observados y1build local pendiente. Citas/líneas, reutilización, SQLite/FK/4FTS y restauración fueron comprobados. La base operativa no se reemplazó ni recibió esos inventarios. Es evidencia de contraste de declaraciones públicas, no aplicabilidad a proyectos privados ni estado instalado.

Pendientes: otros ecosistemas/lockfiles, specifiers o selección de entornos si posteriormente se autorizan y necesitan; aplicabilidad instalada/patches downstream siempre requiere evidencia propia. `no_local_advisory` y `outside_observed_ranges` nunca significan seguro.
